For Developers

This section contains various information that may be useful for developing and understanding the package in more detail.

Data Flow

The following diagram illustrates the process of data handling in OhMyCH, including iteration, deserialization, and returning data to the user:

                              +-------------------+
                              |   Input Data      |
                              |  (Vector{UInt8})  |
                              +-------------------+
                                       |
                +----------------------+-----------------------+
                |                                              |
 +---------------------------+               +------------------------------------+
 |         RowBinary         |               |     RowBinaryWithNamesAndTypes     |
 +---------------------------+               +------------------------------------+
                |                                              |
                v                                              v
 +---------------------------+               +------------------------------------+
 |        User type `T`      |               |    Parse Column Names and Types    |
 |   (e.g., `T` or `Tuple`)  |               |                                    |
 +---------------------------+               +------------------------------------+
                |                                              |
                +----------------------+-----------------------+
                                       |
                                       v
                              +-------------------+
                  +---------> |  Start Iteration  |
                  |           +-------------------+
                  |                    |
                  |                    v
                  |           +-------------------+
                  |           | Read Binary Chunk |
                  |           +-------------------+
                  |                    |
                  |                    v
                  |           +-------------------+
                  |           |  Deserialize Row  |
                  |           +-------------------+
                  |                    |
                  |                    v
                  |           +-------------------+
                  |           | Return Row to User|
                  |           +-------------------+
                  |                    |
                  |                    v
                  |           +-------------------+
                  |           |   Check for EOF   |
                  |           |   - More Data?    |
                  |           +-------------------+
                  |                    |
                  +--------------------+
                                       |
                                       v
                             +-------------------+
                             |   End Iteration   |
                             +-------------------+

Serializer

OhMyCH.Serializer — Type
Serializer{I<:IO}

Custom IO wrapper for (de)serializing binary data streams.

source
OhMyCH.serialize — Function
serialize(s::Serializer, ::Type{T}, value::T) -> Int
serialize(s::Serializer, value) -> Int

Writes the byte representation of value to buffer s.

Examples

julia> import OhMyCH: Serializer, serialize, deserialize

julia> s = Serializer();

julia> serialize(s, UInt8, UInt8(10))
1

julia> serialize(s, Int32, Int32(100))
4

julia> serialize(s, Float64, Float64(1000.0))
8

julia> serialize(s, String, "Hello, World!!!")
16

julia> seekstart(s.io);

julia> deserialize(s, UInt8)
0x0a

julia> deserialize(s, Int32)
100

julia> deserialize(s, Float64)
1000.0

julia> deserialize(s, String)
"Hello, World!!!"

Binary iterators

OhMyCH.RowToBinaryIter — Type
RowToBinaryIter{T}

Iterator for converting rows into serialized binary data in chunks.

Fields

  • items::AbstractVector{T}: Collection of rows to be serialized.
  • chunk_size::Int: Maximum size of serialized chunk in bytes.
  • serializer::Serializer: Serializer used to encode rows.
  • current_start::Int: Current position in the list of items.
  • items_per_chunk::Int: Number of rows (items) included in a single chunk.
  • plan::Union{Nothing,Vector{Pair{Int,CHType}}}: With a plan, field i of every row is written as the ClickHouse type the plan pairs it with (see insert_plan); without one, rows are written from their Julia types.
source
OhMyCH.BinaryToRowIter — Type
BinaryToRowIter{F<:RowBinary, R}

Iterator over a RowBinary result — bytes without a schema — yielding rows of type R, whose fields say what the bytes are. Carrying R as a type parameter means eltype is concrete, so collect(iter) produces a properly-typed Vector{R} rather than Vector{Any}.

Without a schema a DateTime64 field (NanoDate) can only be decoded by guessing its precision from the magnitude of the value, which is right for instants after 2001-09-09 (nanoseconds) or between 2001 and 2286 (milliseconds). A RowBinaryWithNamesAndTypes result knows the precision and decodes every instant exactly — prefer query over query_binary for DateTime64 columns.

Fields

  • row_type::Type{R}: Data type whose fields define row cell types.
  • binary::RowBinary: Binary format containing the serialized data.
  • column_names::NTuple{N,Symbol}: Column names.
  • column_types::NTuple{N,Type}: Column types.
source
OhMyCH.SchemaRowIter — Type
SchemaRowIter{R}

Iterator over a RowBinaryWithNamesAndTypes result yielding rows of type R. The result's own schema drives decoding: every column is read as the ClickHouse type the server declared (a DateTime64(3) is scaled by 3, a Decimal(18, 8) is 18 digits wide), then handed to the field of R that names it, coerced to the field's type (coerce). Columns no field asks for are read and dropped.

With R a NamedTuple built from the schema (what eachrow and collect do), names and types are the result's own. With a user's R, fields are matched to columns by name — a struct or NamedTuple — or by position — a Tuple — and a field without a column is an ArgumentError before the first row is read.

Fields

  • binary::RowBinaryWithNamesAndTypes: the result being read.
  • columns::Vector{Column}: the result's schema, in wire order.
  • positions::Vector{Int}: for each field of R, the index of its column.
source

Schema-driven (de)serialization

OhMyCH.deserialize — Method
deserialize(s::Serializer, t::CHType)

Reads one value whose ClickHouse type is t. Unlike deserialize(s, ::Type), a DateTime64(P) is scaled by its declared precision, so every instant is exact — not only the ones a digit-count heuristic happens to get right.

source
OhMyCH.serialize — Method
serialize(s::Serializer, t::CHType, value) -> Int

Writes value as the ClickHouse type t, coercing it first: an Int into an Int32 column, a DateTime into a DateTime64(3) column (scaled to its precision), a Float64 into a Decimal(18, 8), nothing or missing into a Nullable. Returns the number of bytes written.

source
OhMyCH.insert_plan — Function
insert_plan(client::CHClient, table::AbstractString, ::Type{T}) -> (sql, plan)

How rows of type T go into table. A table name becomes INSERT INTO table (a, b, …) FORMAT RowBinary naming the columns the fields of T name (a struct or NamedTuple) or, for a Tuple, the table's columns in order (ALIAS and MATERIALIZED ones excluded — the server computes those); every field is then written as its column's own type, see serialize. A field that names no column is an ArgumentError before anything is sent.

A full INSERT INTO … statement is sent as written, and rows are written from their Julia types alone (plan === nothing): the statement already says which columns, in which order.

source
OhMyCH.column_positions — Function
column_positions(::Type{T}, columns::Vector{Column}; what) -> Vector{Int}

For each field of the row type T, the index of the column that feeds it. A struct or NamedTuple is matched by field name; a Tuple positionally. Throws ArgumentError naming every field without a column, and the columns that were available, so a typo in a field name is caught before any byte is sent or decoded.

Query parameter formatting

OhMyCH.parameters_to_strings — Function
parameters_to_strings(values::NamedTuple) -> Vector{Pair{String,String}}
parameters_to_strings(values::T) -> Vector{Pair{String,String}}

Method that formats parameter values into the form required for the request.

See more in ClickHouse Docs.

Examples

julia> parameters_to_strings((
           null = nothing,
           string = "123",
           vector = [1.0, 2.0, 3.0],
       ))

 "param_null" => "\N"
 "param_string" => "123"
 "param_vector" => "[1.0,2.0,3.0]"

julia> parameters_to_strings((
           tuple = (1, -2, 3.0, true, NaN, Inf),
       ))

 "param_tuple" => "(1,-2,3.0,1,nan,+inf)"

           dict = Dict(
               "int_key" => 1,
               "null_key" => nothing,
           ),
       ))
1-element Vector{Pair{String, String}}:
 "param_dict" => "{'int_key':1,'null_key':NULL}"

 0x04
 0x22
    ⋮
 0x00
 0x00
